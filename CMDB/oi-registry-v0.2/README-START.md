# OI Registry v0.2 — СВТ, комплектующие, работы, квартальные проверки и состав ОИ

**Готовый пакет обновления поверх v0.1**, установленной в `/home/admsec/ZGT/CMDB/oi-registry-v0.1`. Сохраняет имеющиеся данные PostgreSQL, учётные записи и оригиналы документов. Текущий OpenProject и IB Platform не меняет.

## Добавлено в v0.2

- Электронный формуляр каждой СВТ: hostname, доменное имя, IP, текущий статус корпуса/опечатывания.
- Отдельный реестр комплектующих с типом, моделью, заводским номером, датой добавления и историей вывода. Типы: системный блок, диск, клавиатура, мышь, блок питания, монитор и др.
- Общие МФУ и принтеры на уровне ОИ и отдельная история разрешений СВТ на их использование (многие ко многим).
- СЗИ: наименование, версия, реквизит лицензии, дата окончания, история установки и вывода.
- Журнал обращений: кто обратился, когда, тема, неисправность, ссылка на задачу OpenProject (вручную).
- Журнал работ: исполнитель, время, вид работы, действия, результат, обязательное состояние корпуса после ремонта, прикреплённый акт. Исторические записи не перезаписываются.
- Квартальные осмотры: проверяющий, дата, чек-лист, категории нарушений, итог, корректирующие меры и подтверждающий акт. Отчёт по пропущенным проверкам за квартал.
- Снимки комплекта ОИ: помимо СВТ включают перечисленные компоненты, доступные МФУ, СЗИ, hostname, домен и состояние корпуса. Изменение диска видно при сравнении с исходным снимком.
- Заявки на изменение состава с маршрутом статусов и ручной ссылкой на пакет работ OpenProject. Утверждение снимка требует приложить документ и подтверждение администратора.
- Быстрый поиск в реестре СВТ по hostname, домену, серийному номеру комплектующего и общему МФУ.

## Ограничения

- Связь с OpenProject пока **по ID**: автоматическое создание задач ещё не включено.
- Не реализованы отдельные права на конкретные ОИ/СВТ, маршруты согласования несколькими должностными лицами, обязательная периодическая рассылка напоминаний, выгрузки PDF/XLSX и автоматическая техническая инвентаризация Windows/Linux.
- Только роли `admin` (редактирование) и `viewer` (чтение). Для производственной эксплуатации нужны предметные роли (администратор СВТ, сотрудник ИБ, аттестующий, аудитор), раздельные права и защита данных.
- В журнал нарушений лучше сохранять **категорию, факт, дату, ссылку на служебный акт и необходимые меры**, а не сами запрещённые материалы или их содержимое. Не переносите в пилот конфиденциальные, секретные, персональные данные без нужных организационных и технических мер.
- «Снимок утверждён» в CMDB не означает официально аттестован; решение фиксируется уполномоченным сотрудником по документам.

## Обновление существующей v0.1 на Debian

1. Перенесите `oi-registry-v0.2.zip` в общую папку `/media/sf_/`.
2. Под root:

```bash
cd /home/admsec/ZGT/CMDB
unzip -n /media/sf_/oi-registry-v0.2.zip -d /home/admsec/ZGT/CMDB
bash /home/admsec/ZGT/CMDB/oi-registry-v0.2/scripts/upgrade_from_v01.sh
```

Скрипт сначала создаст резервные копии БД, документов и предыдущих исходников в каталоге `oi-registry-v0.1/backups/`, затем соберёт новое API, применит миграции и заменит веб-интерфейс. **Не удаляйте папку `oi-registry-v0.1`, `.env` или Docker volumes.**

После обновления откройте http://127.0.0.1:8085 и зайдите со старым логином и паролем. Нового администратора создавать не нужно.

## Проверка

```bash
cd /home/admsec/ZGT/CMDB/oi-registry-v0.1
docker compose ps
docker compose exec -T oi-api alembic current
bash scripts/smoke.sh
```

Ожидается `0003_asset_lifecycle (head)`. Для нового функционала: создать тестовую СВТ → открыть карточку → **Состав, работы, проверки** → добавить диск, МФУ, СЗИ, обращение, ремонт и проверку. В карточке ОИ кнопка **Комплект и изменения**.

**Важно:** установка v0.2 в НОВУЮ отдельную папку с другим `.env` поверх уже существующих Docker volumes не является обновлением; используйте только `upgrade_from_v01.sh`.
