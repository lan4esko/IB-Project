# OpenProject — эксплуатация и роль в контуре ИБ

## Текущая установка

**[ФАКТ]** `17.9.1`, установлен **на хосте Debian**, а не в Docker Compose проекта OI Registry. Применяются systemd-юниты `openproject-web-1`, `openproject-worker-1`, ранее также наблюдались `apache2` и host PostgreSQL. Путь пакета `/opt/openproject/`, пакетный CLI `openproject`.

```bash
sudo openproject run bundle exec rake version
sudo systemctl status openproject-web-1 openproject-worker-1 apache2 --no-pager
sudo journalctl -u openproject-web-1 -n 100 --no-pager
sudo journalctl -u openproject-worker-1 -n 100 --no-pager
sudo openproject run backup
```

Уточнить на месте URL/порт/сертификаты, actual DB storage, настройки mail, SMTP, список проектов, резервирование репозиториев и приложений. **Нельзя** восстанавливать OpenProject из архива OI Registry.

## Процессный дизайн под 60 ОИ

- **Один постоянный проект OpenProject на ОИ**, не отдельный проект для каждой СВТ.
- Задачи по жизненному циклу: формирование, классификация/категорирование (если применимо), специальные обследования/исследования, аттестация, ввод, эксплуатация, ремонт, переаттестация, вывод из эксплуатации.
- Задачи по отдельным СВТ — Work Packages внутри соответствующего проекта ОИ; в реестре OI Registry остаётся карточка СВТ и факт проверки.
- Сроки не назначать всем ОИ одинаковые — брать из карточки аттестации и утверждённого календаря мероприятий.

Это **целевая процессная структура**; не все шаблоны и автоматическое создание проектов реализованы. Идентификаторы проектов заполнить и проверить до интеграции.

## Проверка связи с CMDB

В OI `information_objects.openproject_project_id` хранится число. Наличие этого числа **не подтверждает существование проекта или доступ сервисного пользователя**. Проверять через веб UI/API v3 OpenProject. Для API использовать отдельную малопривилегированную сервисную учётную запись, ограниченную нужными проектами и типами Work Package.

## Аварии и безопасные действия

- 502/503 в OpenProject: проверить Apache, web-юнит, worker, host PostgreSQL, свободное место, миграции только после бэкапа.
- Ошибка Background worker: `journalctl` и статусы очереди; не перезапускать все сервисы, если отказ изолирован.
- Ошибка выдачи API ключа: проверить пользователя/проект/permissions, не переносить admin token в `.env` CMDB.
- Бэкап: командой `sudo openproject run backup` создаются компоненты PG, attachments, Git/SVN и конфигурации (конкретные пути уточняются по выводу); сделать автономную копию **всех** элементов комплекта, убедиться что восстановление на стенде описано и испытано.
- Обновлять OpenProject отдельно от CMDB; бэкап перед пакетным upgrade, проверка совместимости API после обновления.
