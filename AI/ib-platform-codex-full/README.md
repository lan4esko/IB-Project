# ТЗ: автономная корпоративная ИИ-платформа советников по ИБ

**Версия пакета:** 2.0, 12 октября 2026 г.
**Исполнитель:** Codex в Ubuntu VM; хост — Astra Linux Special Edition 1.7.6 «Смоленск».

## С чего начать

1. Открой этот каталог в VS Code внутри Ubuntu.
2. Передай агенту содержимое `CODEX_START.md` (или укажи ему открыть этот файл).
3. Обязательно оставь в корне `AGENTS.md`: в нём правила разработки, доступа к данным и отчётности.
4. Полное ТЗ: `TZ_CODEX_IB_PLATFORM_FULL.md` — **основной источник требований**; остальные файлы — вспомогательные, не заменяют его.
5. На хосте Astra при первой возможности **оператором**, отдельно от Codex, собрать данные `ops/astra_qemu_diagnose.sh`. Ничего в Astra не обновлять ради VM.
6. При разработке на машине с интернетом использовать только открытые публичные акты и синтетические/обезличенные документы. Реальные материалы, составляющие гостайну, не подключать к этому пилоту.

| Путь | Назначение |

## Важные границы

Проект не является «аттестованным» решением и не допускает обработки государственной тайны автоматически. Локальная изоляция сети — лишь один из защитных факторов. Совместимость с Astra/QEMU требует **фактической диагностики установленного QEMU/libvirt**, а не предположения на основании номера Astra.

OpenProject — Community Edition, без патчей для обхода платных функций. Интеграция Thunderbird в рамках MVP — календарная подписка iCalendar на просмотр.

## Как принимать результат

Codex обязан передать работающую систему, исходный репозиторий, pinned Docker/Compose, подготовленный offline bundle, документацию, реальные логи тестов и отчёт `PASS/FAIL/BLOCKED` с доказательствами. Само наличие документа ТЗ не является подтверждением выполнения этих требований.
