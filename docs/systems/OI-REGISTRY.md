# Подсистема OI Registry (CMDB) — функциональность и сопровождение v0.4

**[ФАКТ]** Точка входа `http://127.0.0.1:8085`. Рабочие исходники `/home/admsec/ZGT/CMDB/oi-registry-v0.1`; имя каталога не переименовывали при переходе v0.1 → v0.4.

## Назначение и функции по релизам

| Этап | Что введено | Примечание |
|---|---|---|
| v0.1 / `0001_initial` | карточки ОИ/СВТ, настраиваемые поля, документы, история полей, аудит, CSV | удаление данных ограничено |
| v0.2 / `0002_configuration`, `0003_asset_lifecycle` | снимки конфигурации, изменения, комплектующие, МФУ, ПО СЗИ, ремонты, квартальные проверки, опечатывание | baseline — учётный, не документ об аттестации |
| v0.3 / `0004_governance` | `admin/editor/requester`, заявки ответственных, история аттестации/уведомления, недельный отчёт, расширение МФУ | actor/audit заполняет сервер |
| v0.4 / `0005_automation` | локальный планировщик контрольных записей, дедупликация, знакомство с мероприятием, ручной OpenProject API v3 publish, единый архив | **полная обратная синхронизация не готова** |

## Основные таблицы (ORM SQLAlchemy)

`users`, `login_sessions`, `information_objects`, `assets`, `field_definitions`, `field_values`, `field_assertion_revisions`, `field_evidence`, `documents`, `audit_events`, `configuration_baselines`, `configuration_changes`, `asset_components`, `shared_peripherals`, `asset_peripheral_access`, `asset_security_tools`, `service_requests`, `work_entries`, `asset_inspections`, `oi_proposals`, `planned_activities` (точные имена перепроверять по ORM и миграциям). Схема управляется Alembic. Не редактировать таблицы вручную в обход приложения: потеряется прикладной аудит.

## Доступы

| Роль | Возможности | Ограничения |
|---|---|---|
| `admin` | администрирование пользователей, утверждение, конфигурация, публикация OpenProject | даже у admin нет веб-команды удаления всей PostgreSQL БД |
| `editor` | карточки ОИ/СВТ, ремонт, проверки, рассмотрение заявок, личный недельный отчёт | не управляет пользователями и не публикует OpenProject admin-endpoint |
| `requester` | подача сведений/документов по своему ОИ, просмотр своих заявок | не меняет официальный реестр и не смотрит чужие вложения заявок |

При проверке ролей использовать три **тестовые** учётные записи и реальные HTTP коды `401/403`. До помещения чувствительных данных в CMDB необходимо отдельно подтвердить разграничение доступа по конкретным ОИ: v0.4 не предлагает полноценный per-OI ACL для всех ролей.

## Карточка ОИ

Код, название, классификация, местоположение, стадия, `attestation_issued_on`, `attestation_valid_until`, `attestation_document_id`, `attestation_notice_days` (стандартное значение в модели 90 дней, но может быть изменено), `openproject_project_id`, примечания. Не использовать универсальный «законодательный срок» вместо аттестационных данных конкретного ОИ.

## Карточка СВТ

Серийный и инвентарный номер, тип/модель, ОС, сетевая принадлежность/IP/hostname/domain, опечатывание, статус. Отдельные компоненты с серийными номерами (диски, системный блок, клавиатура, мышь, БП, монитор и т.д.), история установки/списания. Ремонтный запрос отдельно от записи выполненных работ и акта квартальной проверки.

## МФУ

Устройство относится к ОИ, может быть привязано к нескольким СВТ. Паспорт: производитель/модель, заводской и учётный номера, характеристики МНИ. Разрешение подключения **СВТ–МФУ**: способ подключения, драйвер/версия/контрольная сумма, SMB ссылка на доверенный пакет. Не сохранять пароль SMB в поле и не запускать драйвер при регистрации карточки. История обновления паспорта МФУ аудируется с `before/after`.

## Аудит и отчёт

`audit_events`: actor_id, timestamp, action, entity, request_id/source_ip/details. Журнал подтверждает использование **учётной записи**, а не личность за клавиатурой. Отчёт недели формируется через `GET /api/reports/weekly?week_start=...&format=csv`; администратор может посмотреть другого пользователя; обычный пользователь — себя. Проверять, что фоновые изменения планировщика и ручные работы различаются.

## Планировщик

`oi-worker` запускает `python -m app.scheduler` при старте и далее с `sleep 86400`. Это не cron в 03:00. Время итогового квартала определяется серверным кодом, инспекция квартальная календарная. Дедупликация: `inspection:<asset_id>:<YYYYQ#>` и `attestation:<oi_id>:<date>`; PostgreSQL unique key плюс advisory lock. Возможные состояния: `open`, `acknowledged`, `satisfied`, `superseded`; публикация `not_sent`, `published`, `needs_review`.

**Типовые ошибки:** отсутствует контрольная дата аттестации → напоминания не будет; статус СВТ retired/decommissioned → не создаётся инспекция; неправильный `openproject_project_id` → нельзя отправлять без ручной сверки.

## API/проверка

`GET /api/health/live`, `GET /api/health/ready`, `GET /api/auth/me`, `GET /api/objects`, `GET /api/assets`, `GET /api/dashboard`, `GET /api/audit`, `GET /api/automation/preview`, `GET /api/automation/activities`, `POST /api/automation/plan`, `POST /api/automation/activities/{id}/publish` (admin). Swagger FastAPI может быть доступен на `/docs`, но в эксплуатации пользуйтесь только контролируемыми маршрутами/аутентификацией.
