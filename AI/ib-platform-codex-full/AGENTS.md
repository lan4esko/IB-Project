# AGENTS.md — постоянные инструкции для Codex

## Цель
Реализовать полноценную офлайн-корпоративную ИИ-платформу ИБ строго по `TZ_CODEX_IB_PLATFORM_FULL.md`, включая все приложения A–S и traceability matrix. Русский язык интерфейса и документации обязателен. Не останавливаться на прототипе и не объявлять функцию готовой без работающего кода и тестов.

## Порядок действий
1. Перед началом целиком изучить ТЗ, `CODEX_START.md`, `docs/OPEN_QUESTIONS.md`.
2. Диагностировать Ubuntu и ресурсы; создать `STATUS.md`, `DECISIONS.md`, `TEST_REPORT.md`, `docs/ENVIRONMENT.md`.
3. Работать фазами P0–P9, каждую разбивать на коммиты с запускаемыми тестами.
4. Сначала рабочая безопасная вертикаль MVP: local chat → RAG с цитатами → доступ к документам → реестр → документы → OpenProject → offline.
5. Все решения/несоответствия документировать. Исключать фиктивные заглушки и фальшивые тесты.

## Самые жёсткие запреты
- НЕ менять Astra Linux 1.7.6 «Смоленск», QEMU/libvirt, ядро, МРД/МКЦ. Codex выполняется внутри Ubuntu и не управляет хостом. Версия QEMU неизвестна, её обязан проверить оператор хоста.
- НЕ загружать в облачный Codex реальные секретные/гостайные документы, реальные SID/ACL, служебные выгрузки и пароли.
- НЕ объявлять обычную Ubuntu VM пригодной для работы с гостайной. Гостайна — отдельный допущенный проект.
- НЕ принимать решения об ACL по системному промпту и НЕ использовать служебный token без проверки прав конечного пользователя.
- НЕ осуществлять сетевую публикацию документов, запись в AD, исполнение Bash/PowerShell на внешних серверах или создание задач в OpenProject без явного действия уполномоченного пользователя.
- НЕ использовать пиратские активаторы/взлом лицензирования. OpenProject Community Edition — базовый компонент.
- НЕ использовать `latest`, плавающие зависимости, внешние CDN, недокументированные облачные API в offline-runtime.

## Корпоративные данные
До официального подтверждения политики доступа — только публичные и синтетические материалы. Внутренние конфиденциальные материалы: только после проверки ACL, изоляции и документированного разрешения; гос. тайна — НЕТ в этом MVP.

## Качество
Любое нормативное утверждение — только по действующей подтверждённой редакции загруженного документа с проверенной ссылкой. При отсутствии данных — отказ от заключения. «Нет доказательства» ≠ «не выполнено». Изменения состояния должны сохранять историю.

## Текущая реализация
Пользователи: 1–5; CPU-only; исходно 16 vCPU / 32GiB, на хосте 32 Xeon cores/64GiB и HDD RAID. Поддержать увеличение ресурсов, но не считать их бесконечными. Использовать Open WebUI/Ollama/OpenProject, по возможности без форков; backend FastAPI и БД для собственных предметных функций. Все сервисы доступны по TLS во внутренней сети, Ollama/БД закрыты от прямого доступа.

## Reporting
После каждой фазы: что создано, что запущено, какие тесты реально пройдены, что недоступно по внешней причине, как повторить проверку, что осталось. Каждый тест `PASS` имеет log/artifact evidence. Не утверждать, что гипервизор совместим, пока нет сведений с Astra.
