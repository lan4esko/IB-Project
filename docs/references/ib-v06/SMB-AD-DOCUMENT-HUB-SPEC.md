# IB Platform — техническое задание v0.6: Document Hub, SMB/AD, OCR, управление форматами

Статус: **проект требований, к реализации**, дата: 2026-10-14.
Исходное состояние: работающий Backend v0.5.0, PostgreSQL, Ollama, RAG lexical/semantic/hybrid, документы с версиями, Docker Compose; тестовый стенд Debian 13 (2 vCPU, 6 GiB RAM). Реальное SMB-подключение пока не выполнено.

## 1. Цель

Организовать одну общую базу знаний для всех **авторизованных** пользователей с максимально простой загрузкой, автоматической индексацией, детальной диагностикой ошибок и безопасной синхронизацией существующей SMB-шары объёмом около 100 ГБ. Оригиналы на SMB остаются на файловом сервере. Большие LLM хранятся локально, но на тестовом стенде не запускаются.

## 2. Подключение SMB с доменной сервисной учётной записью

- Создать в AD отдельную сервисную учётную запись, например `DOMAIN\\svc_ib_ai_ro` (условное имя), с разрешением **Read/List** в общих разрешениях SMB (share) и NTFS ACL только на требуемых папках. Проверить отсутствие прав `Write`, `Modify`, `Delete`, `Change permissions`.
- Указывать точку подключения UNC вида `//fileserver.example.local/IB_Documents`; она может находиться на DC или на отдельном файловом сервере — доменная идентичность остаётся той же.
- **Вариант для пилота:** на хосте Debian установить `cifs-utils`; подключить SMB/CIFS 3.x от сервисной учётной записи, используя отдельный root-only файл credentials (0600), `ro,nosuid,nodev,noexec`; не хранить пароль в `.env`, Compose, API, UI, Git, журналах. Приложение получает только хостовый bind mount в контейнер воркера `:ro`.
- **Целевая конфигурация:** Kerberos и keytab с корректным AD DNS, синхронизацией времени и обслуживанием обновления ключей; реализация после проверки возможностей инфраструктуры. NTLMSSP с TLS не следует путать: SMB3 encryption/signing настраиваются отдельно на сервере и клиенте; соединение должно использовать требуемую корпоративной политикой защиту.
- Не требуется вступление Debian в домен только ради pilot CIFS credentials; для Kerberos-интеграции и AD SSO требования иные.
- Учетная запись SMB предназначена **для системной фоновой синхронизации**, не для входа сотрудников в веб-интерфейс. LDAP/AD SSO пользователей — отдельная задача последующего этапа.
- Обязательные проверки: аутентификация, список каталогов, возможность чтения файла, **отсутствие записи**; удостовериться, что пароли нигде не логируются.
- Отказ сервера / истечение пароля / ошибка монтирования => `source_unavailable`, повторные попытки с увеличивающейся задержкой, **не** удалять документы из индекса и не интерпретировать пустой каталог как удаление файлов.
- Запрет обхода SMB-каталога по относительным `..`, перехода к внешним ссылкам / симлинкам / DFS вне согласованного корня; следовать только настройкам, явно разрешенным администратором.

## 3. Фильтрация форматов через UI

Настройка в разделе «Источники → SMB → Форматы». Для каждого расширения: `Включено / Выключено`, `Парсер`, `OCR (если применимо)`, `Лимиты`, `Пояснение`. Политика **разрешительного списка (allowlist)**, не «обрабатывать всё кроме запрещённого».

| Форматы | По умолчанию | Обработка |
| --- | --- | --- |
| `.pdf` | Включено | Извлечение текстового слоя; OCR отдельных страниц без извлекаемого текста |
| `.docx` | Включено | Абзацы, таблицы, заголовки; без исполнения макросов |
| `.xlsx` | Включено | Листы, заголовки, строки и ячейки с координатами; `read_only`, `data_only`; без исполнения формул |
| `.txt`, `.md`, `.csv` | Включено | Детектирование кодировки, ограничение строк и размеров |
| `.pptx` | Включено | Текст слайдов, заметок (если поддерживается парсером) |
| `.odt`, `.ods`, `.odp` | Отключено | После отдельного тестирования |
| `.doc`, `.xls` (устаревшие бинарные) | Отключено | Требуют отдельного безопасного конвертера; не выдавать как успешно проиндексированные |
| `.docm`, `.xlsm`, `.pptm` | Отключено | Макросодержащие форматы; при включении — только безопасное извлечение, без исполнения |
| `.jpg`, `.png`, `.tiff` | Отключено | Отдельная опция OCR изображений |
| `.zip`, `.rar`, `.7z`, `.exe`, `.dll`, `.ps1`, `.bat`, `.iso`, прочие | Отключено | Никакого выполнения или рекурсивной распаковки; статус `skipped_unsupported` |

- Сверять расширение **и** тип/сигнатуру/внутреннюю структуру файла, не доверять одному имени. Несовпадение => `suspicious_type`, пропуск и запись причины.
- Неизвестные файлы по умолчанию **не открывать, не индексировать и не запускать**. В общем списке показывать количество и причину пропуска; без «карантина с исполняемым содержимым» внутри API.
- Файлы с паролем, повреждённые и чрезмерно большие помечать `requires_attention`/`failed`, не обходить защиту паролем.
- Настройка отдельной политики по каждому источнику и исключение директорий и масок (например `~$*`, `*.tmp`, `.git`, backup-каталоги), case-insensitive расширения.

## 4. OCR и безопасность обработки

- PDF: сначала читать текстовый слой, а OCR применять **постранично** там, где текст отсутствует или явно недостаточен; не прогонять OCR повторно по уже распознанным страницам.
- Для OCR использовать Tesseract `rus+eng` в выделенном низкоприоритетном worker с ограничениями CPU/RAM/времени, разрешая обработку по одному файлу. Сканированные PDF с большим количеством страниц обрабатывать батчами, сохраняя прогресс.
- Результаты RAG должны хранить номер страницы PDF или лист/строку Excel; оригинал/версию/SHA-256 связывать с фрагментом.
- Обработка файлов в процессе, который не имеет прав записи на SMB; не выполнять активное содержимое Office, формулы, макросы и внешние ссылки; ограничить zip decompression ratio, число записей и общий извлечённый размер.
- Антивирусная проверка — опция следующего этапа; для потенциально исполняемых и несовпадающих форматов первична стратегия skip-by-default.

## 5. Очередь, консистентность, отказоустойчивость

- Развести HTTP загрузку и длительную обработку. API создаёт запись файла и задачу в PostgreSQL и быстро возвращает идентификатор; самостоятельный `ib-document-worker` обрабатывает задания.
- Для очереди использовать PostgreSQL (`FOR UPDATE SKIP LOCKED`, lease/heartbeat, `retry_at`, `attempts`, ограниченный backoff, idempotency key); при перезапуске lease просроченного задания возвращает задачу в обработку.
- Конвейер SMB: enumerate -> фильтр -> metadata -> проверка стабильности size+mtime на двух сканированиях -> потоковый SHA-256 -> staging -> парсер/OCR -> текстовые фрагменты -> embeddings -> атомарная публикация новой версии индекса.
- Предусмотреть корректность при изменениях во время чтения: сравнить metadata перед/после, при несоответствии повторить позже. Перегрузка файла одного и того же SHA-256 не переиндексирует документ повторно.
- Пока версия индексируется, прошлый **готовый** индекс остаётся доступен. Переход к новой версии только после полной успешной обработки.
- Потеря SMB и ошибки доступа не означают удаления данных. Отметка об удалении возможна только после нескольких успешных полных сканирований источника и периода ожидания; политики «archive/missing/delete» раздельны.
- Не переносить все 100 ГБ: сохранять метаданные и выбранные текстовые фрагменты/эмбеддинги. Временную копию файла хранить ограниченное время; кэш оригиналов по необходимости и под квотой.
- На нынешней VM: один worker, ограниченные batch sizes, ограничение размера/страниц, контролируемая очередь OCR, никаких больших LLM в памяти.

## 6. UI: два сценария

### Пользователь «Библиотека»
- Кнопка «Добавить файлы» и drag-and-drop, многократный выбор; после передачи автоочередь — без ручной кнопки `index`.
- Таблица: Имя / источник / дата / размер / тип / версия / состояние / причина ошибки / поиск; индикаторы прогресса и кнопка «Повторить» для ошибок.
- Поиск включает только опубликованные документы; вся библиотека доступна всем авторизованным сотрудникам. Аудит действий сохраняется.

### Администратор «Источники»
- Добавить источник по UNC, выбрать настроенный mount/secret reference, выбрать папки и исключения; кнопки «Проверить соединение», «Синхронизировать», «Пауза», «Повторить ошибки».
- Отдельная вкладка «Форматы»: чекбоксы расширений, режим PDF OCR (`авто/выкл/принудительно`), ограничение размера, исключения по имени.
- Статистика: обнаружено / новых / обновлено / проиндексировано / пропущено / ошибок / в очереди, отметка последнего **успешного** сканирования, связь с AD/SMB без отображения секрета.
- **Не** показывать пароль сервисной учётной записи. Настройка секрета на хосте администратором инфраструктуры; UI хранит только ссылку на конфигурацию.

## 7. Проект API v0.6

- `GET/POST /api/v1/sources` — список и создание источника (только admin для записи).
- `POST /api/v1/sources/{id}/test` — проверить доступность, read-only и UNC.
- `GET/PUT /api/v1/sources/{id}/formats` — получить/сохранить allowlist расширений.
- `POST /api/v1/sources/{id}/scan` — поставить сканирование в очередь.
- `GET /api/v1/sources/{id}/status` — состояние синхронизации и ошибки.
- `GET /api/v1/ingestion/jobs` — очередь, статусы, ошибки; фильтры.
- `POST /api/v1/ingestion/jobs/{id}/retry` — повторить безопасно.
- `POST /api/v1/documents/upload-batch` — загрузка пакета и автоматическое создание заданий.
- Старый документный REST API сохранить ради обратной совместимости; индексирование вручную временно оставить служебным.

## 8. Миграция и модель доступов

- Новые таблицы: `document_sources`, `source_format_rules`, `source_files`, `ingestion_jobs` и необходимые индексы. Изменения схемы через Alembic. Не удалять документы, пользователей, токены и имеющиеся RAG-индексы при миграции.
- **Общая библиотека:** все авторизованные пользователи имеют право чтения и поиска. Старые таблицы document ACL сохранить при первом переходе; единые проверки чтения поменять одновременно для загрузок, скачивания, списка, RAG и цитирований. Не удалять старые ACL до миграции и тестов.
- Источники/подключения/параметры/массовые повторы доступны только ролям администратора; все существенные действия аудируются.

## 9. Минимальные критерии приемки

1. Domain service account с фактическим чтением SMB и отсутствием права записи; пароль не попадает в код, БД, UI и журналы.
2. Подключение и успешный импорт DOCX, XLSX, PDF (текстовый и сканированный) с цитатами на листы/страницы.
3. `.exe` и неизвестное расширение: `skipped_unsupported`, не индексируются, счётчик пропусков виден в UI.
4. Переименование расширения исполняемого файла в `.pdf`: `suspicious_type`, нет индексирования.
5. Сбой SMB не приводит к очистке библиотеки; после восстановления происходит возобновление.
6. Прерывание worker -> восстановление задания, без дублирования версий/индекса.
7. Дубликат SHA-256 => без повторного OCR/эмбеддингов; изменение файла => новая версия после атомарной публикации.
8. Все авторизованные пользователи видят одну библиотеку; неавторизованные не имеют доступа; неадминистраторы не меняют подключения.
9. Нагрузка на стенд с 6 ГБ RAM остаётся контролируемой; большие LLM не запускаются.

## 10. Данные для последующей фактической настройки

Требуется узнать (без передачи секретов в чат): FQDN/IP сервера хранения, имя SMB-шары (UNC), NetBIOS/AD DNS-домен, каталог(и) для индексирования, доступность SMB TCP/445, требования к SMB signing/encryption и будет ли учётка сервисная обычная или Kerberos/keytab. Пароль в чат **не присылать**.
