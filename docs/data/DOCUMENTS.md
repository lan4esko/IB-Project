# Хранение документов, подтверждения и история файлов

## OI Registry

Оригинальные файлы не лежат просто рядом с backend: они находятся в Docker named volume `oi-registry_oi_documents_data`, используются через `/data/documents` в контейнере FastAPI. PostgreSQL `documents` хранит metadata `storage_key`, SHA256, размер, original_filename, автора и связь supersedes. При обновлении редакции важен контроль версий и связь `field_evidence` с конкретной ревизией полей.

Для резервного копирования OI нужны **обе** части: dump PostgreSQL и volume оригиналов. Поодиночке они могут оставить «осиротевшие» ссылки или файлы. Backup-full включает оба в один архив.

## IB Platform

Оригиналы документов IB Platform лежат отдельно (по compose `ib-platform_documents_data`), метаданные/версии и чанки RAG — в `ibplatform` PostgreSQL. Ollama weights и Open WebUI data могут занимать **другие** volumes. Оригиналы CMDB не автоматически доступны RAG; проектные требования к общей библиотеке не разрешают нарушать ограничения ОИ.

## Классификация и безопасность

Документы ограниченного доступа, ПДн, материалы аттестации могут нуждаться в дополнительных правилах допуска. Не добавляйте файлы документов в Git/обмен через общий Windows folder. Любую ссылку на SMB-драйвер МФУ храните без пароля и проверяйте источник/контрольную сумму.

## Поиск потерянного документа

1. Проверить ID документа и разрешения в UI; ошибки 403 отдельно от отсутствия файла.
2. Проверить состояние `oi-api`, SQL запись документа и путь `OI_DOCUMENT_ROOT` (без вывода секретов).
3. Проверить наличие и содержимое **только метаданных** volume, не исправлять вручную `storage_key`.
4. При фактическом отсутствии файла: сверить `manifest.json` и архив `documents.tar.gz` на отдельном стенде; восстановление в production только через утверждённую процедуру.
