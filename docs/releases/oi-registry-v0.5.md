# Release oi-registry v0.5 — КАНДИДАТ, НЕ ВНЕДРЁН

- Дата подготовки исходников: 2026-10-18.
- Статус: **кандидат к установке**, не считать работающей версией на Debian без журнала внедрения.
- Исходная база: рабочая копия `CMDB/oi-registry-v0.1`, API v0.4.0, Alembic `0005_automation`.
- Кандидат: API `0.5.0`, Alembic `0006_control_rules`.
- Что добавлено: регламенты `control_rules` по ОИ и СВТ, периодичность 1/3/6/12 месяцев, ответственный, локальное планирование, реестр просрочек и сроков, документарное завершение, аудит, ручное чтение статуса OpenProject, серверная пагинация.
- Сроки и применимость не выводятся из нормативного документа автоматически, задаются администратором и требуют утверждения организации.
- Обновление: полная резервная копия v0.4 → копирование изменённых файлов → проверка конфигурации → `docker compose up -d --build oi-api oi-web` → проверка Alembic и API → smoke v0.5.
- Откат: **восстановление согласованной резервной копии v0.4** (БД + документы + исходники), а не слепой `alembic downgrade`.
- Разработка: 28 тестов pytest на изолированной SQLite прошли; миграции v0.4→v0.5→v0.4 и установка схемы с нуля проверены на SQLite. **Тестирование на эксплуатационном PostgreSQL и приемка не выполнялись**.
- Ручные проверки после внедрения: запись правил/документов, идемпотентность планировщика, объектные фильтры, публикация в OpenProject, отказ при таймауте, чтение статусов, доступы admin/editor/viewer/requester, восстановление из резервной копии.
- Git commit/tag: заполняется после включения изменений в Git; образ/дигест: заполняется после сборки.
- Номер бэкапа, SHA256, факт DR-теста, протокол приёмки: **ожидаются от администратора**.
