# OI Registry v0.4 — автоматический контроль мероприятий ИБ

**Пакет обновления для существующей установки v0.3** (ревизия `0004_governance`). Не запускайте `scripts/install.sh` из каталога релиза; не удаляйте тома Docker.

## Назначение

- Контроль окончаний сроков аттестации ОИ по **внесённой дате** и заданному сроку уведомления (нет универсального срока, придуманного программой).
- Отдельные мероприятия по квартальной проверке каждой действующей СВТ.
- План без дублей в PostgreSQL. Ключи мероприятий привязаны к ОИ и дате аттестации либо к СВТ и календарному кварталу.
- Фиксация факта зарегистрированной проверки; ознакомление с напоминанием **не равнозначно выполнению проверки**.
- Отдельная вкладка **«Мероприятия ИБ»** в браузере (фильтры, статус, ознакомление).
- Планировщик в контейнере `oi-worker`, выполняющий только локальное планирование один раз примерно в сутки.
- Интеграция через OpenProject API v3 реализована, **отключена по умолчанию**. Главный администратор после конфигурации может вручную отправлять по одной проверенной задаче. При неопределённом исходе HTTP-запроса повторная отправка блокируется до ручной сверки по ключу.
- Централизованная согласованная резервная копия PostgreSQL, документов, `.env`, исходников и Docker-конфигурации в **одном архиве** в `/home/admsec/ZGT/CMDB/BACKUPS/` с SHA-256. Архив содержит пароли/ключи: закрыть доступ и копировать на независимый носитель.

## Установка на Debian

Скачайте `oi-registry-v0.4.zip` на основной компьютер и поместите в общую папку VirtualBox `/media/sf_/`.

```bash
cd /home/admsec/ZGT/CMDB
unzip -n /media/sf_/oi-registry-v0.4.zip -d /home/admsec/ZGT/CMDB
bash /home/admsec/ZGT/CMDB/oi-registry-v0.4/scripts/upgrade_from_v03.sh
```

Установщик убеждается, что установлена v0.3, делает централизованный backup **до** обновления, тегирует прежний Docker-образ, собирает новый, мигрирует `0004_governance → 0005_automation`, запускает API и планировщик. **Не меняет** действующий `.env`, PostgreSQL OpenProject, IB Platform и Ollama.

После установки:

```bash
cd /home/admsec/ZGT/CMDB/oi-registry-v0.1
docker compose ps
docker compose exec -T oi-api alembic current
bash scripts/smoke_v04.sh
docker compose --profile automation logs --tail=40 oi-worker
ls -lh /home/admsec/ZGT/CMDB/BACKUPS/
```

Откройте `http://127.0.0.1:8085`, выполните `Ctrl+Shift+R` и выберите «Мероприятия ИБ». Данные реестра и персональные учётные записи сохранены. Для тестирования лучше использовать учебные ОИ и СВТ.

## OpenProject: безопасное подключение (опционально)

Интеграция требует в `oi-registry-v0.1/.env` отдельной **сервисной** учётной записи OpenProject с доступом только к нужным проектам. Ни ключ API, ни пароли не отправляйте в переписку. Не используйте ключ главного администратора OpenProject. Нужен ID типа работы, разрешённого в соответствующих проектах.

```dotenv
OI_OP_SYNC_ENABLED=true
OI_OP_BASE_URL=https://адрес-openproject-в-локальной-сети
OI_OP_API_KEY=<вставить локально, не отправлять в чат>
OI_OP_TYPE_ID=1
```

`OI_OP_TYPE_ID=1` — **пример**; фактический ID следует определить в OpenProject. Если OpenProject доступен только через HTTP на хосте Debian, допустим осознанный локальный тест по `http://host.docker.internal`, отдельно установив `OI_OP_ALLOW_LOCAL_HTTP=true`. Для постоянной работы рекомендуется HTTPS и доверенный сертификат. После изменения `.env` выполнить:

```bash
cd /home/admsec/ZGT/CMDB/oi-registry-v0.1
docker compose up -d --no-deps --force-recreate oi-api
```

Теперь только главный администратор может **по одной записи** отправлять мероприятие из вкладки «Мероприятия ИБ». Это никогда не запускается автоматически планировщиком. В случае ошибки или таймаута состояние `needs_review` означает необходимость найти ключ `[OI-REGISTRY:...]` в OpenProject **до** повтора; специальной автоматической процедуры повтора нет.

## Ограничения текущей версии

- Регистрация квартальной проверки не означает, что все замечания устранены; статус `satisfied` означает лишь наличие записи проверки в данном квартале.
- Задача, уже опубликованная в OpenProject, не закрывается автоматически при изменении срока аттестации; требуется ручное согласование.
- Планирование в фоне по циклу от времени запуска контейнера, а не строго в 03:00. При запуске контейнера проверка выполняется сразу.
- Период квартальной проверки сейчас календарный, не индивидуальный график для каждой СВТ.
- Резервная копия создаётся локально, **не защищает от поломки диска**. Нужно копировать архив и его `.sha256` на отдельное защищённое хранилище и регулярно тестировать восстановление.
- Автоматическая публикация сразу сотен задач в OpenProject преднамеренно отсутствует: требуется контроль нагрузки и корректности сопоставления проектов.

## Для сменяющего администратора

- **Рабочий каталог:** `/home/admsec/ZGT/CMDB/oi-registry-v0.1`
- **Единый каталог новых бэкапов:** `/home/admsec/ZGT/CMDB/BACKUPS`
- **Рабочая БД:** Docker named volume `oi-registry_oi_postgres_data`, **не копировать его файлы на работающем сервере**.

- **Конфигурация и секреты:** `oi-registry-v0.1/.env`, права доступа `600`.
- **Ручной бэкап:** `bash scripts/backup_full.sh` из рабочего каталога.
- **Проверка:** `bash scripts/verify_backup.sh /home/admsec/ZGT/CMDB/BACKUPS/<имя>.tar.gz`.
- **Запуск:** `cd /home/admsec/ZGT/CMDB/oi-registry-v0.1 && docker compose up -d && docker compose --profile automation up -d oi-worker`.
- **Восстановление:** только на отдельном стенде согласно `docs/BACKUP_AND_RESTORE.md`. Никогда не копировать архив с `.env` на незащищённый SMB.
