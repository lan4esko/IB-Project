# Пилот «Госсектор»: системные промпты и справочник НПА для IB Platform

**Версия:** 0.1 • **Подготовлено:** 14.10.2026 • **Назначение:** тестирование поведения советников на вашем Docker/Ollama/Open WebUI + FastAPI v0.5.

## Что входит

- `prompts/00_SHARED_POLICY.md` — общая политика проверяемых ответов и защиты от галлюцинаций.
- 5 готовых ролей в `prompts/01...05...`.
- `registry/acts.json` — справочные карточки 12 актов со ссылками, без текстов норм.
- `registry/directory_for_rag.txt` — справочник, который можно зарегистрировать в RAG v0.5.
- `scripts/install_ollama_profiles.sh` — создаёт 5 локальных профилей Ollama **на маленькой** `qwen3:0.6b`; не загружает большие LLM в оперативную память.
- `scripts/seed_registry_v05.py` — через FastAPI админом загружает указатель и индексирует как текстовый документ (не база нормативных положений).
- `tests/scenarios.md` — 8 контрольных сценариев.

## ВАЖНО — источник и актуальность

Страница https://regulhub.kaspersky.ru/industry/gosudarstvennyy-sektor представляет **интерактивный подбор по целям и типам объектов**. Из неё нельзя получить достоверный полный список НПА для *конкретной* организации, пока неизвестны характеристики её систем.

Карточки RegulHub — сторонние обзоры, **не официальные тексты**. Указатель актов лишь помогает навигации: он не содержит обязательных пунктов, сроков и технических мер. Для нормативного заключения отдельно загрузите **полные действующие редакции** из официальных источников (проверив редакции, изменения, введение в силу). Следите за изменениями актов и проверяйте отдельные пункты по первоисточникам.

По состоянию на октябрь 2026: приказ ФСТЭК №117 от 11.04.2025 вступил в силу с 01.03.2026, заменив №17; приказ №137 от 08.05.2026 внёс поправки с разными датами вступления (01.09.2026 и 01.03.2027). Нельзя использовать изменения 2027 года как обязательные в 2026-м без основания.

Документы с гостайной в данный пилот не загружать. Для иных документов соблюдать классификацию и режим допуска; отключённые ACL приложения не расширяют полномочия на источник SMB.

## Развёртывание на Debian 13

1. Поместите архив в `/media/sf_/` VirtualBox.
2. Запустите только эти команды (профили создаются, **модели не запускаются**):

```bash
cd /home/admsec/ZGT/AI
unzip -n /media/sf_/ib-platform-govsec-prompts-v0.1.zip -d /home/admsec/ZGT/AI
cd /home/admsec/ZGT/AI/ib-platform-govsec-prompts-v0.1
bash scripts/install_ollama_profiles.sh
```

3. Проверка:

```bash
docker exec ib-ollama ollama list
docker exec ib-ollama ollama ps
```

Новые Ollama-модели `ib-gos-regul:0.1`, `ib-gos-gis:0.1`, `ib-gos-pdn:0.1`, `ib-gos-kii:0.1`, `ib-gos-plan:0.1` могут стать видны в Open WebUI после обновления перечня моделей. Они используют одну базовую малую модель без скачивания пяти копий весов.

**Осторожно:** `qwen3:0.6b` подходит для проверки интерфейса, но **не** для корректного применения сложных НПА. Основные `qwen3.5:27b` и `gpt-oss:20b` уже сохранены в Ollama; запускать их на 6 ГБ RAM не требуется. На производительном сервере перенесите системные инструкции в Open WebUI → Workspace → Models и выберите большую базовую модель. Если Open WebUI переопределяет системный промпт Ollama, задайте его прямо в настройках Workspace-модели.

## Подключение справочника к отдельному RAG v0.5 (по желанию)

```bash
cd /home/admsec/ZGT/AI/ib-platform-govsec-prompts-v0.1
python3 scripts/seed_registry_v05.py
```

Скрипт запросит пароль admin **без его печати**. При каждом запуске создаст новый документ (не запускайте многократно). Импортируется только указатель названий, не полный текст НПА. Ваша `IB Platform FastAPI` и RAG **не становятся автоматически доступными внутри Open WebUI** от этого действия: для сквозной интеграции потребуется мост API/инструмент, либо отдельная загрузка документов через Workspace → Knowledge.

## Первый тест без ложных правовых выводов

В Open WebUI выберите `ib-gos-regul:0.1` и задайте:

> Какие данные нужны, чтобы определить применимость требований для ГИС, которая обрабатывает ПДн и может быть объектом КИИ? Не выдумывай пункты НПА; перечисли документы, которые надо проверить.

После установки действующих полных текстов в систему — проверяйте `tests/scenarios.md`. Нет текста — модель должна отказать в выводе о конкретных обязательных пунктах.
