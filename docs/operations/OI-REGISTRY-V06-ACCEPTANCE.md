## 3. Проверки в тестовой БД — только после явного решения администратора

Каждый следующий пункт выполняется на **тестовых** ОИ и СВТ, после согласования времени, режима и возможных последствий:

- [ ] Создать тестовый ОИ и 2 тестовых СВТ, отдельно сохранить исходные значения.
- [ ] Экспортировать ZIP; открыть `manifest.json`, `data.json`, `tables/*.csv` без запуска сервиса; убедиться, что вложения отсутствуют.
- [ ] `merge`: проверить предпросмотр трёх вариантов, добавление новой СВТ и отказ при расхождении полей.
- [ ] `copy`: проверить новые коды ОИ/СВТ и сохранность исходных записей.
- [ ] `replace`: проверить изменения паспортов и `retired` отсутствующих СВТ; историю ремонтов не удалять.
- [ ] В каждом режиме запросить отдельную фразу/чекбокс; проверить 403 на неверную фразу, 409 на устаревший/повторный план.
- [ ] Проверить права `viewer`/`editor`/`requester`: экспорт и импорт — отказ (403) без admin.
- [ ] Проверить невозможность импорта повреждённого, слишком большого или неподходящего ZIP.
- [ ] Проверить аудит (пользователь, время, тип операции, ОИ, hash архива без содержимого).
- [ ] Проверить полную резервную копию и **тестовое восстановление** отдельно от текущей базы.

## 4. Раздельная эксплуатация

- [ ] Рабочая v0.5 по-прежнему обслуживается через `8085` и миграцию `0006_control_rules`.
- [ ] Тестовая v0.6-alpha использует `-p oi-registry-v06-test`, отдельные volumes и `18085`.
- [ ] `.env` тестовой версии не добавлен в Git, пароль администратора не показан в переписке/логах.
- [ ] `oi-worker` production не пересоздан из тестового образа.

## 5. Решение о Git / релизе

Только после документального аудита и секрет-сканирования создать отдельный docs commit и отправить **тестовую ветку**. Публикация feature ветки — не приёмка и не перенос в `main`. Без проверки PostgreSQL, импорта/экспорта и DR в `docs/RELEASES.md` оставить состояние «alpha/тестирование».

**Поля фактического протокола** (заполнять локально, без персональных данных и секретов): дата, Git SHA, `alembic current`, SHA256 образа API, номер тестового ОИ, состав тестов, результат, дефекты, ответственный, решение о выпуске.
