# Установка OI Registry v0.5 на Debian 13

**Статус: регламент для будущего внедрения, не факт установки.** Исполнять администратору в обслуживаемое окно. Этот пакет содержит только изменённые исходники и документацию, без `.env` и без дампов.

## Подготовка

1. Остановить массовые изменения в реестре; удостовериться, что CI и резервное копирование исправны.
2. Из `/home/admsec/ZGT/CMDB/oi-registry-v0.1` выполнить `bash scripts/backup_full.sh` (скрипт кратковременно останавливает запись API и worker); сохранить идентификатор и SHA256 полученного архива вне репозитория. Рекомендуется тестовое восстановление.
3. Зафиксировать `docker compose ps`, `docker compose exec -T oi-api alembic current` (ожидается `0005_automation`), `git rev-parse HEAD`; убедиться, что состояние рабочего Git каталога известно.
4. Выделить ветку Git: `git switch -c feature/oi-registry-v0.5` на **чистой** основной ветке перед распаковкой обновления.
5. Применить предоставленный пакет изменений в корне `/home/admsec/ZGT`; предварительно сравнить изменяемые файлы. Не перезаписывать локальные `.env`.

## Развёртывание

```bash
cd /home/admsec/ZGT/CMDB/oi-registry-v0.1
docker compose config -q
docker compose up -d --build oi-api oi-web
docker compose exec -T oi-api alembic current
bash scripts/smoke_v05.sh
docker compose logs --tail=80 oi-api
```

При использовании `oi-worker` он должен запускаться с обновлённым образом приложения: после проверки нового образа выполнить `docker compose --profile automation up -d --force-recreate oi-worker`. Не включать планировщик, пока не принято решение о регламентах. Сами новые правила при обновлении **не создаются автоматически**.

## Приёмка

- Войти под admin, открыть «Мероприятия ИБ», создать пилотное правило для одного тестового ОИ, задать первичную дату и исполнителя.
- Запустить «Обновить локальный план» дважды; проверить, что дубликатов нет и полномочия editor/viewer/requester соблюдены.
- Загрузить акт во вкладке «Документы», завершить пилотное мероприятие с его ID. Убедиться в наличии записи `control_completed` в аудите.
- Проверить подсчёт просрочек, статус `completed`, фильтр ОИ и пагинацию.
- Если OpenProject включён отдельно администратором — вручную создать одну тестовую задачу и сверить её статус. `Closed` в OpenProject не меняет локальный статус до проверки акта.
- Зафиксировать фактический SHA/git-коммит, `alembic current`, протокол smoke, время и результат DR-теста.

## Безопасный откат

Если миграция или функциональная проверка не проходят, остановить сервисы, вернуть **согласованный** снимок исходников, PostgreSQL и документов из одной полной резервной копии v0.4, после чего повторить smoke v0.4. `alembic downgrade 0005_automation` технически возможен, но **удалит поля подтверждения выполнения и привязку правил v0.5**. Не использовать его для рабочего отката данных без согласованного плана миграции и копии данных. Если правила v0.5 уже использовались, сначала выгрузить их для аудита.
