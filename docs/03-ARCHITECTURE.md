# Архитектура ZGT: ответственность, данные, взаимодействие

## Концепция

1. **OpenProject** — процессный контур: проекты ОИ, регламентные мероприятия, сроки, исполнители, задачи и история работы. Установлен на Debian как пакет; PostgreSQL OpenProject принадлежит самому OpenProject.
2. **OI Registry / CMDB** — системный реестр ОИ и ~1200 предполагаемых СВТ, документов, утверждённых конфигураций, инвентаря, проверок, выдач доступа к МФУ, ремонта, заявок, журналов изменений. Взаимодействие с OpenProject осуществляется только через предусмотренные API/ID; **прямого SQL между БД нет**.
3. **IB Platform** — отдельная база нормативных документов и поиск/советники с локальным Ollama, API Gateway, Open WebUI. Не является частью OI Registry и не должна автоматически получать всю чувствительную CMDB.
4. **Git** — управление версиями исходников и документации; не хранилище рабочих БД и не средство аварийного восстановления данных.
5. **Резервные копии** — по отдельным политикам для каждой БД/системы. Единый OI archive не охватывает OpenProject/IB Platform.

## Принцип владения данными

| Сущность | Система-владелец | Реплика/ссылка |
|---|---|---|
| ОИ, жизненный цикл, срок аттестации | OI Registry | `openproject_project_id` (ссылка, не FK в другой БД) |
| СВТ, комплектующие, серийные номера | OI Registry | OpenProject как задачи на обслуживание |
| Ремонт, квартальные осмотры, МФУ | OI Registry | Плановые задачи OpenProject по ручному подтверждению |
| Учётные записи OI Registry и аудит действий | OI Registry | В OpenProject не синхронизируются автоматически |
| Work packages, назначения, статусы задач | OpenProject | `openproject_work_package_id` в CMDB; **обратная синхронизация не реализована** |
| Нормативные документы, RAG чанки | IB Platform | отдельно от документных доказательств CMDB |
| Модели, веса, prompt-профили | Ollama/Open WebUI | AI Gateway выбирает модель, не изменяет CMDB напрямую |

## Основные процессы

### Создание ОИ

Ответственный `requester` → заявка и разрешённые вложения → оператор БД `editor` проверяет → создаётся официальная карточка OI Registry, аудит. При дальнейшей автоматизации проект OpenProject должен быть создан/привязан отдельным контролируемым действием.

### Аттестация

OI Registry хранит **фактическую** контрольную дату `attestation_valid_until` и период уведомления `attestation_notice_days`; планировщик создаёт контрольную запись только по заполненным данным. Общий срок действия не задаётся системой. Утверждение baseline CMDB **не заменяет** аттестационный документ.

### Квартальный контроль СВТ

`oi-worker` → локальный `planned_activity` с ключом `inspection:<asset_id>:<год>Q<квартал>` → осмотр в OI Registry → статус `satisfied`; отмеченное ознакомление не считается проверкой. При необходимости человек публикует одну задачу OpenProject вручную.

### Связь с OpenProject

Администратор настраивает `OI_OP_*` в `.env`, проверяет ID реального проекта и ID типа Work Package, вручную отправляет мероприятие. При неопределённом результате запроса `needs_review`; автоматического повторения нет. Автозакрытие/двусторонний workflow **план**.

### ИИ / документы

Загрузка → сохранение оригинала и метаданных → индексация и чанки → русский FTS/semantic (различающиеся режимы) → Gateway формирует вопрос Ollama → ответ с серверными источниками. Модель может ошибаться, нормативные утверждения проверяются по действующей редакции источника.

## Отказоустойчивость и единые точки отказа

Одна VM/диск = единая точка отказа нескольких независимых приложений. Docker restart-политика **не обеспечивает** HA и не заменяет внешний бэкап. Отказ хоста затрагивает все сервисы. Для изолированного контура нужны отдельный защищённый носитель копий и план возврата сервисов, а не произвольная сеть в Интернет.

## Основные архитектурные решения

- Рабочее имя каталога CMDB сохраняется `oi-registry-v0.1` после обновления v0.4.
- Изменения структуры CMDB — через Alembic, текущая проверенная миграция `0005_automation`.
- OpenProject не помещать в контейнеры CMDB и не восстанавливать из OI-backup.
- По умолчанию не публиковать мероприятия автоматически в OpenProject.
- Не отключать аудит для снижения нагрузки и не разрешать правку автора изменений через клиент.
- Документация и конфигурация (без секретов) — в Git; БД и секреты — отдельно.
