# Госcектор РФ — пакет первичных PDF для IB Platform (RAG) v1

Дата подготовки каталога: 15.10.2026. **Это установщик корпуса, НЕ архив с заранее скачанными нормативными PDF.** Текущая среда подготовки не разрешает прямое скачивание внешних файлов; официальный текст будет получен на вашем Debian при запуске `download` и сохранён локально. В комплекте 19 проверенных прямых ссылок на публичные PDF и утилита, использующая только стандартную библиотеку Python.

Цель: дать RAG **полные исходные тексты, а не только справочные карточки**. Источники подобраны вручную по разделу [«Государственный сектор»](https://regulhub.kaspersky.ru/industry/gosudarstvennyy-sektor), разделам актов ФСТЭК/ФСБ/Правительства и первичным документам. Касаются ГИС, ИСПДн, КИИ, ГосСОПКА, защиты информации, построения и аттестации ИС. Это **не исчерпывающая правовая экспертиза** всех актов, применимых конкретному органу.

## Главная оговорка об актуальности

Многие PDF на сайте Kaspersky содержат **старые редакции**. Например, скачиваемый PDF 149-ФЗ маркирован редакцией июля 2023 года, а файл ПП №676 — состоянием на август 2023 года, хотя сама карточка ПП №676 упоминает изменения 2024 года. Приказ ФСТЭК №117 от 11 апреля 2025 г. вступил в силу 1 марта 2026 г., но опубликованный базовый PDF не содержит поправки приказа №137 от 8 мая 2026 г.: основная часть действует с 1 сентября 2026 г.; одна норма — с 1 марта 2027 г. Добавлен отдельный PDF №137 с официальным источником для сверки.

**Не представляйте этот корпус как полностью актуальную консолидированную нормативную базу.** Для юридически значимых выводов по каждому акту нужно сверить редакцию и дату действия с https://publication.pravo.gov.ru / https://pravo.gov.ru и ФСТЭК/ФСБ. Статус источника записан в каждом индексируемом файле. PDF скачиваются с публичных сайтов; соблюдайте условия их использования и не распространяйте материалы с чужим оформлением вне рамок разрешённого использования.

## Установка в вашей Debian 13 VM

Перенесите этот ZIP в `/media/sf_/` и распакуйте (не затрагивает ваш backend):

```bash
cd /home/admsec/ZGT/AI
unzip -n /media/sf_/ib-govsec-rag-corpus-v1.zip -d /home/admsec/ZGT/AI
cd /home/admsec/ZGT/AI/ib-govsec-rag-corpus-v1
```

Если утилит нет:

```bash
apt-get update
apt-get install -y poppler-utils
```

**Скачайте PDF в каталог корпуса.** Сеть нужна только на этом шаге (модели при этом не запускаются):

```bash
python3 govsec.py download
```

Получите `corpus/pdf/*.pdf`, `corpus/metadata/*.json`, `corpus/download_report.json`. Загрузка последовательная, с контролем PDF-сигнатуры, размерами, SHA-256, таймаутами и повторными попытками. Повторный запуск не скачивает валидные существующие PDF заново.

**Извлеките страницы из PDF, разделите большие акты на документы для v0.5:**

```bash
python3 govsec.py prepare
```

Получите `corpus/rag/<id>/part-NNN.md` и `corpus/prepare_report.json` с номерами страниц и редакциями. Страницы без текстового слоя автоматически отмечаются, а не выдаются как успешно распознанные. Для обработки сканов:

```bash
apt-get install -y tesseract-ocr tesseract-ocr-rus tesseract-ocr-eng
python3 govsec.py prepare --ocr
```

OCR идёт **последовательно**, только по страницам без текста; исходные PDF не изменяются. Контролируйте качество распознавания вручную, особенно таблицы и юридические формулировки.

**Импортируйте в наш работающий FastAPI v0.5:**

```bash
python3 govsec.py import
```

Скрипт запросит пароль `admin` без отображения, авторизуется по `http://127.0.0.1:8001`, загрузит Markdown и автоматически выполнит *lexical* индексацию каждого фрагмента. Токен и пароль не записываются на диск и не выводятся. Прогресс сохранён в `corpus/import_state.json`: после сбоя команду можно запустить повторно, без повторного создания успешно обработанных документов. При изменении исходников повторный импорт создаст новый документ; сохраните журнал предыдущих версий для ревизии.

**Не включайте сразу `semantic` на всех PDF в пилотной VM:** это займёт время и потребует ресурсов. Сначала добейтесь, чтобы лексический поиск находил конкретные пункты. Позже мы построим batch-embedding worker для v0.6.

```bash
python3 govsec.py status
```

## Проверка результата

```bash
# количества загруженных документов и частей, не раскрывая содержание
python3 govsec.py status

docker exec ib-db psql -U ibplatform -d ibplatform -c 'SELECT count(*) FROM documents;'
docker exec ib-db psql -U ibplatform -d ibplatform -c 'SELECT count(*) FROM document_chunks;'
```

Примечание: в нашей схеме v0.5 таблица фрагментов называется `document_chunks` (не `rag_chunks`). Скрипт импортирует **только в действующую систему**, а не создает новый Docker/PostgreSQL.

Примеры вопросов для тестирования — `TEST_QUESTIONS.md`.

## Почему не загружаем сами PDF одним файлом

У текущего RAG v0.5 есть ограничения: 20 страниц PDF и 48 фрагментов (~480 знаков каждый) на один документ, не более 2 МБ на исходный файл. Поэтому большие акты предварительно разбиваются на UTF-8 Markdown объёмом около 11,5 тыс. символов; в каждом сохраняются ссылки на исходный PDF, дата, признак историчности и номера страниц. Это не меняет код вашего API и не требует расширения RAM.

## Исключения

- Документы о государственной тайне и узкоспециальные требования — только после отдельного уточнения сферы применения.
- Устаревший приказ ФСТЭК №17 не индексируется как действующий.
- Продуктовые рекомендации и рекламные подборки Kaspersky не импортируются в первичную нормативную базу.
- Отдельные ГОСТы защищены авторскими/лицензионными условиями, их тексты нельзя считать свободно доступными для пакетного копирования.

## Структура

- `catalog.json` — 19 ссылок, назначение, ограничения по редакциям.
- `govsec.py` — загрузка, контроль PDF, извлечение страниц, OCR (опционально), разбиение, импорт и возобновление.
- `TEST_QUESTIONS.md` — сценарии приёмочных тестов RAG и советников.
- `corpus/` — появится после выполнения команд на Debian; в ZIP текстов нормативных актов и PDF нет.
