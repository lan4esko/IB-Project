# Проверка безопасности перед публикацией ZGT в GitHub

**Блокирующее условие:** в переданном снимке обнаружена строка с паролем администратора OpenProject внутри материалов `open-project/`. Пароль здесь **не воспроизводится**. Если он используется, немедленно заменить его, проверить журналы доступа и следы публикации.

Важно: простое удаление секрета из текущего файла не удаляет его из предыдущих коммитов. Очистка истории Git и, при необходимости, отзыв скомпрометированных ключей/паролей выполняются отдельной согласованной процедурой; force-push на общий репозиторий без плана запрещён.

## Минимальные проверки перед push

```bash
cd /home/admsec/ZGT-v06-test
# Локальные изменения и готовые к публикации файлы
git status --short
git diff --cached --name-only
# Отсечь типовые имена секретных файлов из индекса
git ls-files | grep -Ei '(^|/)(\.env($|\.)|id_rsa$|id_ed25519$|[^/]+\.(pfx|p12|pem|key|pgdump|dump|sqlite|db)$)' || true
# Только имена подходящих файлов, значения/пароли НЕ печатать
```

Это **не полное** обнаружение секретов: реальные пароли могут быть встроены в `.md`, `.yaml`, `.sh`, `.py`. Используйте проверку истории и файлов специальным сканером секретов, настройте защиту репозитория; вывод с обнаруженными значениями храните приватно. Проверять и старые коммиты. Не добавлять `/media/sf_/`, дампы, архивы ОИ, `.env`, приватные ключи, экспорт документов и реальные сетевые паспорта.

## Порядок разблокировки публикации

1. Установить, попадал ли секрет в отправленные на GitHub коммиты/клоны.
2. Сменить пароль и отозвать затронутые токены независимо от истории Git.
3. Согласовать безопасную очистку истории/репозиториев при необходимости.
4. Проверить ветку на секреты, приватные документы, историю и наличие актуальных `.gitignore`.
5. Опубликовать **только после** устранения рисков и решения администратора.
