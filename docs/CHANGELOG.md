# Журнал обновления документации и системы

## docs-1.0 — 2026-10-18

- Создан единый `docs/` для Debian/VirtualBox, OpenProject, OI Registry, IB Platform, RAG/Ollama/Open WebUI, Git и резервных копий.
- Добавлены редактируемые схемы Mermaid: контекст, развёртывание, поток заявки.
- Сверены границы фактов, исходников и запланированных функций; отдельно обозначены неизвестные параметры стенда.
- Добавлены аварийные инструкции, восстановление по отдельным контурам, offline/airgap регламент, ведение релизов и Git hook контроля документации.
- Добавлены формы инцидента, восстановления, инвентаризации и протокола релиза.

## История приложений, зафиксированная по ранее предоставленным журналам

- OI Registry v0.1: базовые ОИ/СВТ, документы, настраиваемые поля и аудит.
- OI Registry v0.2: hardware lifecycle, MFP, ремонты, квартальные проверки и снимки конфигурации.
- OI Registry v0.3: роли, заявки, сроки аттестации, недельный отчёт.
- OI Registry v0.4: планировщик, дедупликация мероприятий, опциональная ручная OpenProject публикация, централизованный архив backup и исправление cache/UI после установки.
- IB Platform: backend v0.5, GovSec RAG/AI Gateway и тестовые advisor-профили; Document Hub v0.6 — проект.

Здесь указывается **документированное** изменение и его подтверждённый статус. Новый код или миграция без обновления этого журнала не должны сливаться в стабильную ветку.

## OI Registry v0.5 — кандидат к внедрению (2026-10-18)

- Подготовлен слой настраиваемых контрольных правил по ОИ/СВТ с планированием, ответственными и периодичностью.

## OI Registry v0.6-alpha — обязательный выбор режима при импорте ОИ

- Добавлены три режима импорта паспорта ОИ и СВТ: объединение / отдельная копия / замена паспорта и вывод отсутствующих СВТ из эксплуатации.
- Введён обязательный предпросмотр, одноразовое повторное подтверждение перед транзакцией, проверка целостности и актуальности состояния, аудит операции.
- Добавлен автономный ZIP-экспорт паспорта ОИ, СВТ и CSV-истории ремонтов/заявок для чтения вне приложения.
- **Ограничение:** документы и история работ не восстанавливаются импортом в этой версии; это не полноценный аварийный бэкап.
- Код и автотесты подготовлены отдельно от рабочего сервера; состояние внедрения не подтверждено.

- Сверены API `object_transfer.py`, `main.py`, миграция `0007` и frontend с требованиями к переносу ОИ.
- Добавлен корневой GitHub README и индекс документации, матрица требований, формат ZIP, подробный регламент импорта/приёмки и предпубликационная проверка.

- Статус v0.6-alpha уточнён: тестовый UI/вход подтверждены, но тестирование импорта на PostgreSQL и восстановление пока не задокументированы.

- **Риск до push:** учётные данные OpenProject из ранней копии репозитория требуют ротации и очистки доступной истории Git.

## OI Registry v0.6.1-alpha — 20.10.2026 (кандидат для тестового стенда)

- Исправлена модель аттестационного документа: ссылка SMB как текст, без требования ID из внутреннего реестра.

- Добавлен проект HTTPS-конфигурации для тестовой VM и инструкции остановки устаревших Compose-проектов.
- Испытания в рабочем PostgreSQL, реальный SMB-доступ и защищённая публикация ещё не подтверждены.
