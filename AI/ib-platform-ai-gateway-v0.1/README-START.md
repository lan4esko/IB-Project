# IB Platform — AI Gateway v0.1 (для Open WebUI)

**Назначение:** объединить работающий Backend v0.5, общий RAG, Ollama и уже установленный Open WebUI в единый браузерный чат ИБ-советников.

**Что не делает:** не меняет структуру PostgreSQL, не удаляет ACL, не заменяет Document Hub v0.6, не копирует секретные документы в Open WebUI Knowledge, не запускает большую Qwen3.5 27B или GPT-OSS 20B, не пишет задачи в OpenProject.

Проверено локально на исходниках v0.5: 4 специальных теста AI Gateway + 7 регрессионных тестов backend. Это не гарантия работоспособности на удалённой Debian — после установки выполните smoke-тест.

## 1. Резервная копия и распаковка

На Debian с правами root. Передайте архив `ib-platform-ai-gateway-v0.1.zip` в `/media/sf_/` через общую папку VirtualBox.

```bash
cd /home/admsec/ZGT/AI/ib-platform
STAMP=$(date +%Y%m%d-%H%M%S)
cp -a backend "../backend-pre-ai-gateway-$STAMP"
cp -p .env "backups/env-pre-ai-gateway-$STAMP"
chmod 600 "backups/env-pre-ai-gateway-$STAMP"

cd /home/admsec/ZGT/AI
unzip -n /media/sf_/ib-platform-ai-gateway-v0.1.zip -d /home/admsec/ZGT/AI

cd /home/admsec/ZGT/AI/ib-platform
bash ../ib-platform-ai-gateway-v0.1/scripts/install_gateway.sh
```

Установщик:
- останавливается, если backend не похож на v0.5;
- добавляет `app.ai_gateway` в FastAPI, с предварительным бэкапом `main.py`;
- добавляет `compose.gateway.yaml`;
- генерирует отдельный случайный `IB_GATEWAY_API_KEY` в `.env`, **не печатая ключ**;
- не запускает, не перезаписывает контейнеры и не запускает миграции.

Если `IB_GATEWAY_API_KEY` уже задан, скрипт его не изменяет.

## 2. Собрать и перезапустить только API

```bash
cd /home/admsec/ZGT/AI/ib-platform

dcg() {
  docker compose \
    -f compose.yaml \
    -f compose.backend.yaml \
    -f compose.postgres.yaml \
    -f compose.auth.yaml \
    -f compose.documents.yaml \
    -f compose.rag.yaml \
    -f compose.gateway.yaml \
    "$@"
}

dcg config -q
dcg build ib-api
```

После успешного build:

```bash
dcg up -d --no-deps ib-api
curl -fsS http://127.0.0.1:8001/health/live
echo
curl -fsS http://127.0.0.1:8001/health/ready
echo
```

Ожидается `0.5.0`, `ready`, PostgreSQL с версией `0004_rag_chunks`; Gateway является **добавкой к v0.5**, поэтому номер версии самого backend пока не меняется.

## 3. Проверить отдельный ключ Gateway

Ключ не пересылайте в чат и не вставляйте в команды, видимые в истории shell. Скрипт проверяет API, не печатая токен:

```bash
bash /home/admsec/ZGT/AI/ib-platform-ai-gateway-v0.1/scripts/smoke_gateway.sh
```

Ожидаются: HTTP 401 без ключа; 200 со списком пяти профилей; 200 для запроса без совпадений (модель не запущена).

## 4. Подключить Open WebUI

Open WebUI должен обращаться из своего контейнера по URL `http://ib-api:8000/openai/v1`, **не** `127.0.0.1:8001` (последний адрес внутри контейнера указывает на сам Open WebUI).

Проверить разрешение имени из контейнера Open WebUI:

```bash
docker exec ib-webui python -c 'import socket;print(socket.gethostbyname("ib-api"))'
```

Если `ib-api` не разрешается, соедините WebUI с backend-сетью, используя слой Compose:

```bash
dcg up -d --no-deps open-webui
```

В Open WebUI (вход под администратором) перейдите к **Admin Panel → Settings → Connections** (путь может немного отличаться в текущей версии). Добавьте провайдера **OpenAI-compatible API**:

- Base URL: `http://ib-api:8000/openai/v1`
- API Key: значение `IB_GATEWAY_API_KEY` из локального `.env` (хранится на Debian; не отправляйте его в переписку)
- Модели: обновите/получите список и выберите `ib-gos-regul:0.2`.

После настройки можно отключить показ прямых моделей Ollama для обычных пользователей, чтобы не обходить RAG. Не удаляйте сами модели Ollama. Ограничьте регистрацию пользователей в Open WebUI и доступ к этому интерфейсу локальной/корпоративной сетью.

## 5. Функциональный тест в браузере

Выберите `ib-gos-regul:0.2`, спросите:

> Какие сведения нужно собрать для определения требований к защите ГИС и персональных данных? Используй только подтверждённые документы из библиотеки, укажи, чего не хватает.

Ожидаем ответ и, если найдены фрагменты, блок "Источники в библиотеке" с идентификаторами `document:...`.

**Критическое ограничение:** сейчас в RAG есть учебный документ и карточки нормативных актов, а не полные официальные тексты. Нельзя считать вывод советника подтверждённой юридической оценкой. При отсутствии подходящих источников Gateway отвечает отказом от нормативного вывода и **не запускает модель**.

Режим поиска по умолчанию `lexical`, чтобы не запускать embedding-модель без необходимости. Для пилотного гибридного поиска можно сменить `IB_GATEWAY_SEARCH_MODE` на `hybrid` в `compose.gateway.yaml` и пересоздать только `ib-api`; это вызовет работу Ollama embeddings и увеличит время ответа.

## 6. Важные ограничения и безопасность

1. В v0.1 **один серверный ключ Open WebUI → Gateway**, поэтому Gateway не знает личность конечного пользователя чата. Это соответствует вашему решению об общей библиотеке для всех допущенных пользователей, но для полноценного пользовательского аудита потребуется отдельная интеграция идентификаторов/SSO. Текущие ACL для обычного API сохраняются, Gateway использует доступ общей библиотеки; сервисный ключ нужно защищать.
2. Сервисный ключ разрешает только GET `/openai/v1/models` и POST `/openai/v1/chat/completions`. Он **не** может авторизоваться в `/api/v1/users`, загрузке документов или OpenProject.
3. Защититесь от произвольной регистрации в Open WebUI и не публикуйте API в Интернет. Ключ переменных окружения может быть прочитан пользователями с административным доступом к Docker — для промышленной среды позже нужен более строгий механизм секретов.
4. Ответ формируется **после полного завершения Ollama-запроса**. Параметр `stream=true` поддерживается через формат SSE, но отправка по токенам ещё не реализована; пользователь может ждать до 90 секунд до первого фрагмента.
5. Источники приписывает сервер, а не языковая модель. Наличие карточки документа не гарантирует актуальности его редакции и применимости нормы.
6. В шлюзе сознательно выключена передача ролей `system` от клиента. В этом пилоте используется последний вопрос пользователя, без длинной истории диалога. Настоящий многошаговый чат и рекомендации с отдельными ссылками на официальные пункты — последующие этапы.

## 7. Откат (без восстановления PostgreSQL)

В каталоге платформы верните резервную копию `backend/app/main.py.pre-gateway-*` или `backend-pre-ai-gateway-*`, уберите слой `compose.gateway.yaml` из `dcg`, соберите старый образ v0.5 и запустите API старым набором Compose-файлов. Миграции базы данных для Gateway нет.
