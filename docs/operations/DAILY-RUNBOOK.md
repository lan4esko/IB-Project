# Регламент эксплуатации: смена, неделя, месяц, релиз

## Ежедневно / при заступлении

| Проверка | Метод | Норма/действие |
|---|---|---|
| Docker и контейнеры | `docker ps`; `docker compose ps` в CMDB | `oi-db/oi-api` healthy, `oi-web/oi-worker` up |
| OI ready | `curl -fsS http://127.0.0.1:8085/api/health/ready` | HTTP 200, БД PostgreSQL |
| Планировщик | `docker compose --profile automation logs --tail=50 oi-worker` | успешная последняя обработка; нет необъяснимого роста дублей |
| Сроки аттестации | вкладка «Мероприятия ИБ» | проверить новые/просроченные; нет гарантии уведомления без заполненной даты |
| IB API / RAG | `curl localhost:8001/health/ready`; `docker logs ib-api` | сервис отвечает; качество ответа отдельно |
| OpenProject | systemd web/worker; URL | доступность сайта, queue/worker |
| Место | `df -h`; `docker system df` | избежать заполнения; НЕ использовать `prune --volumes` |
| Время | `timedatectl status` | корректная синхронизация для аудита и сроков |

## Еженедельно

- Сотрудники получают **личный отчёт за неделю** из OI Registry, сверяют с выполненными работами и документами; главный администратор сверяет отчёты персонально.
- Разобрать открытые ремонты, отсутствие пломб после ремонта, нарушения квартальных проверок, неотправленные задачи и неопределённые `needs_review` OpenProject.
- Проверить наличие свежих резервных копий и наличие внешней защищённой копии вне диска VM. Важно: существование файла != возможность восстановления.
- Проверить ошибки IB RAG/OCR и корректность редакций нормативных документов (в пилоте обновление может быть ручным).
- Просмотреть журналы входа, изменений ролей, необычных экспортов; не выгружать чужие сведения в открытые отчёты.

## Ежемесячно/ежеквартально

- Контроль восстановления тестового OI archive на **отдельном стенде**. Периодичность утверждает владелец системы; как минимум плановая регулярная учебная проверка.
- Проверка бэкапов OpenProject и IB Platform **отдельно**; аварийные учения должны восстановить все зависимости, не только OI.
- Ревизия сервисных прав OpenProject API; проверка ключей и срока их действия без печати значений.
- Сверить фактические Docker image digest, Debian версии/обновления, конфигурацию UI/кэширования и Mermaid-топологию.
- Реестр новых ОИ, списанного СВТ, учётных номеров МФУ, МНИ и драйверов с SMB ссылками.
- По кварталу — факт проведения каждой проверки СВТ, а не только созданная планировщиком задача.

## После любой установки/смены версии

1. Зафиксировать Git commit, старую/новую Alembic revision и образ Docker.
2. Сделать бэкап каждого затронутого слоя, отработать план отката.
3. Изменить документацию и `CHANGELOG.md` в этом же Git изменении; выполнить `docs/scripts/verify_docs.py`.
4. Провести smoke-тест, проверку ролей/экспорта, документов, резервной копии и worker.
5. Подписать краткий протокол приёмки в защищённом локальном учёте, без секретов.

## Отчётность

Формы: [INCIDENT template](../templates/INCIDENT.md), [RESTORE TEST](../templates/RECOVERY-TEST.md), [RELEASE CHECKLIST](../templates/RELEASE-CHECKLIST.md). Назначение конкретных людей/телефонов/замещающих администраторов заполняется **локально**, вне общего Git.
