# Обновление приложений: зависимости, бэкап, приёмка и откат

## Общая дисциплина

До обновления: текущее состояние/версия, версии БД, commit, Docker image digest, наличие проверенной резервной копии, оценка downtime и миграции. Во время: логи установки, не скрывать ошибки. После: smoke, UI/браузер, база, аудит, документы, фоновые задачи, backup и обновлённые docs.

## Откат

- Если миграция **не** выполнена: вернуть старый образ и исходники, убедиться, что схема не изменилась; проверить API и документы.
- Если миграция выполнена: простой Git checkout старого кода может быть несовместим; восстановление из backup на новом стенде или отдельная протестированная downgrade-миграция.
- Worker и исходящие OpenProject публикации на период rollback отключить, избежать повторной отправки/осиротевших ссылок.
- Не обещать автоматический rollback БД там, где его нет.

## IB Platform и OpenProject

IB Platform использует несколько Compose файлов: перед upgrade скопировать установленный backend/Compose, сделать **отдельный** PG + document backup, применить соответствующие миграции, проверить русский FTS/AI Gateway. OpenProject обновлять пакетным способом независимо от Docker, начиная с `openproject run backup`. Пакетные апдейты OpenProject могут изменять API; после него протестировать одну безопасную операцию получения проекта до разрешения CMDB публикаций.
