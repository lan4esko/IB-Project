# Корпус нормативных документов государственного сектора

## Что подготовлено

**[ФАКТ по журналам]** Для пилотной IB Platform ранее загружались около 19 нормативных PDF. При обработке наблюдались примерно 2942 текстовых фрагмента. Числа не являются постоянными: для актуального состояния выполнить инвентаризацию IB PostgreSQL. Подготовлены пакет корпуса `ib-govsec-rag-corpus-v1`, реестр актов и тестовые вопросы.

**[ИСХОДНИК]** RAG/Gateway v0.2 обеспечивает русскоязычный PostgreSQL полнотекстовый поиск через `to_tsvector('russian')`, GIN-индекс, фильтрацию по номеру акта, поиск источников и фрагментов с метаданными документа. Сканированные PDF и ошибки классификации редакций требуют отдельной проверки.

## Процесс контроля достоверности

1. Документ поступает с указанием источника, редакции, даты получения, версии, SHA-256.
2. Извлекается текстовый слой. Если его нет и OCR не реализован/не подтверждён — файл не должен молча стать «успешно проиндексированным».
3. Указываются позиции источников: страницы, пункты, имена файлов, контрольные суммы.
4. Ответ Gateway сопоставляется с **извлечённым текстом**, затем с официальной редакцией акта.
5. Исправления метаданных фиксируются отдельно; изменение названия в БД без проверки фактического PDF может привести к ложным ссылкам.

## Известные ограничения

- Наличие текста PDF в индексе не означает актуальность нормативной редакции.
- Профиль советника на `qwen3:0.6b` способен ошибаться даже при наличии правильного фрагмента.
- Правоприменение по конкретной ГИС/ИСПДн/объекту КИИ зависит от параметров системы и даты действия документа.
- Полный перечень разрешённой для индексации информации и ответственные за обновление источников должны утверждаться организацией.

## При отказе

Проверить health IB API/DB, ревизию FTS, наличие документа и версии, корректность текста/страницы, наличие модели embeddings, журналы индексации. Не проводить необратимое переиндексирование всей библиотеки без резервной копии. При ошибочном ответе сохранить запрос, используемые источники и версию модели в локальном журнале инцидента, не в публичном Git.
