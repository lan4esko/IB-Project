# OI Registry v0.3 — управление сроками, доступами и отчетностью

Это **обновление v0.2**, а не новая инсталляция. Исходное приложение и Docker Compose по-прежнему находятся в `/home/admsec/ZGT/CMDB/oi-registry-v0.1`.

## Реализовано

- Даты аттестации и контроля срока в карточке ОИ, предупреждения в панели обзора, регулируемая глубина предупреждения. Дата **не** рассчитывается из выдуманного нормативного периода. Периодичность и необходимость переаттестации определяет ответственный на основании применимых документов.
- Поля производителя, модели, учётного номера, встроенного МНИ и его номера у МФУ. Для *каждого разрешения СВТ использовать МФУ* хранятся способ подключения, версия драйвера, путь SMB, SHA-256 пакета.
- Три роли: `admin` (главный администратор), `editor` (оператор БД), `requester` (ответственный за ОИ — только заявки). Ранее созданный `viewer` остается читающим пользователем для совместимости.
- Создание персональных учётных записей главным администратором, принудительная смена начального пароля, отключение пользователей с отзывом сессий.
- Заявка ответственного на создание ОИ с возможностью загрузить файл (до 25 МБ); оператор проверяет и утверждает/отклоняет, только после утверждения возникает карточка ОИ.
- Персональный недельный отчёт (неделя понедельник—воскресенье) по событиям и журналу работ, CSV, отчёт главного администратора по конкретному сотруднику.
- Серверный журнал изменений: время, внутренний ID пользователя, тип операции, объект, сведения об изменении, request ID, IP прямого HTTP-клиента (обычно reverse proxy), User-Agent. История работ и проверок сохраняется отдельно.

## Ограничения текущего релиза

- Напоминания видны **в панели управления** при входе; почтовые, фоновые уведомления и автоматическое создание задач OpenProject **ещё не реализованы**.
- SMB-драйвер только регистрируется как путь/метаданные; сервер не скачивает, не проверяет существование SMB-файла и не устанавливает его автоматически.
- Система создаёт журнал аудита на уровне приложения, но **не обеспечивает криптографической неизменности / WORM-аудита**. Для доказательной базы нужны отдельная append-only роль/хранилище, централизованные логи и синхронизированное время.
- Веб-интерфейс и API экспериментальные: перед вводом реальных чувствительных данных нужны TLS/SSO, разграничение доступа к документам, проверка резервного восстановления и аудит безопасности.
- Недельный отчёт отражает *кто зарегистрировал* работу (`created_by`) и отдельно *кого указал исполнителем*. Эти сведения не эквивалентны доказательству фактического исполнения.
- Глобальная автоматическая генерация паролей и подключение AD/LDAP в этот релиз не входят: администратор назначает начальный пароль, который надо сменить при первом входе.

## Установка

1. Сначала убедитесь, что поверх v0.1 уже установлен **v0.2**; у работающего API ревизия миграций должна быть `0003_asset_lifecycle`. Если нет — выполните обновление v0.2.
2. Поместите архив `oi-registry-v0.3.zip` в общую папку VM `/media/sf_/`.
3. В терминале Debian:

```bash
cd /home/admsec/ZGT/CMDB
unzip -n /media/sf_/oi-registry-v0.3.zip -d /home/admsec/ZGT/CMDB
bash /home/admsec/ZGT/CMDB/oi-registry-v0.3/scripts/upgrade_from_v02.sh
```

Обновление делает резервные копии БД, вложений и исходников до миграции. Таблицы не сбрасываются. Образ собирается до остановки API; OpenProject и IB Platform не затрагиваются.

4. Проверка:

```bash
cd /home/admsec/ZGT/CMDB/oi-registry-v0.1
docker compose ps
docker compose exec -T oi-api alembic current
bash scripts/smoke_v03.sh
```

Ожидается `0004_governance (head)`.

## Первое тестирование

- Войдите главным администратором, создайте учетные записи оператора БД и ответственного за ОИ. Временные пароли передавайте защищённым способом.
- Войдите под ответственным: смените первоначальный пароль, подайте тестовую заявку на ОИ.
- Оператор БД принимает заявку, заполняет контрольную дату аттестации, заводит тестовую СВТ и её МФУ. Сохраняет запись выполненной работы.
- Проверьте `Отчёт за неделю` под оператором и тот же отчёт через главного администратора.

Команды и тестовые пароли из документа не являются настройками сервиса. Не присылайте пароли и содержимое `.env` в чат.
