# OI Registry v0.1 — первый рабочий реестр ОИ и СВТ

**Назначение:** отдельный локальный сервис учёта объектов информатизации и СВТ с документальными основаниями для значений полей. Разворачивается на Debian 13 параллельно с OpenProject и IB Platform. Никаких изменений в их базах и Docker-контейнерах не выполняет.

## Что уже работает в пакете

- Вход администратора по паролю, Argon2id, серверная сессия (только hash токена в БД), HttpOnly SameSite-cookie и защита запросов CSRF.
- Реестр ОИ: создание/редактирование, паспорт, классификация/категория как свободный текст, местоположение, статус, **ID проекта OpenProject для будущей синхронизации**.
- Реестр СВТ: заводской/инвентарный номера, модель, ОС и версия, сетевой сегмент, IP, состояние, привязка к ОИ.
- Конструктор типовых (для всех карточек данного типа) и локальных (для одной карточки) полей: текст, число, дата, да/нет, список.
- История изменений значений и журнал аудита; запись редактирования основных атрибутов также попадает в журнал.
- Загрузка PDF/DOCX/XLSX/TXT/MD/CSV до 25 МБ с SHA-256. Файлы не исполняются и не анализируются ИИ.
- Привязка документа к **конкретному значению поля** с типом основания и местом (PDF-страница, пункт, ячейка, текстовая ссылка); если значение поменялось, прежняя привязка помечается исторической.
- Фильтрация СВТ по ОИ, состоянию, сегменту, ОС, общему поиску, настраиваемому полю. CSV-экспорт по действующим фильтрам и выбранным колонкам с защитой от формул в таблицах.
- Пользователь с ролью `viewer` имеет право только чтения, администратор — записи.
- Отдельная БД PostgreSQL 17; файловые оригиналы в отдельном Docker volume; резервное копирование обоих компонентов.

## Не реализовано в v0.1 (не обозначайте как готовое)

- Автоматическое создание/обновление задач через OpenProject API, AD/LDAP-вход, календарь нормативных сроков, утверждаемые снимки аттестованного комплекта, массовый импорт СВТ, PDF/XLSX-отчёты, полноценный просмотр DOCX/XLSX с переходом в ячейку, автоматическое извлечение данных из файлов, OCR и ИИ.
- Указание `openproject_project_id` **не** синхронизирует данные — пока это реквизит связи.
- Нет промышленного разграничения доступа по конкретным ОИ и обязательного согласования изменений. Поэтому не вносите реальные сведения ограниченного доступа до настройки условий их защиты.
- Интеграция с RAG IB Platform не включена и не нужна для базового учёта СВТ.

## Установка

1. Перенесите архив `oi-registry-v0.1.zip` в общую папку VirtualBox `/media/sf_/`.
2. На Debian под root:

```bash
mkdir -p /home/admsec/ZGT/CMDB
unzip -n /media/sf_/oi-registry-v0.1.zip -d /home/admsec/ZGT/CMDB
cd /home/admsec/ZGT/CMDB/oi-registry-v0.1
bash scripts/install.sh
```

Установщик создаёт `.env` с уникальными случайными секретами (chmod 600), проверяет `docker compose config -q`, поднимает три собственных контейнера. Если порт 8085 занят, измените `OI_PORT` в `.env` до установки и повторите.

3. Создать администратора (пароль вводится в терминал скрыто, минимум 12 символов):

```bash
bash scripts/create_admin.sh
```

4. Проверить:

```bash
bash scripts/smoke.sh
```

5. Открыть **http://127.0.0.1:8085** в браузере **на самой Debian VM**. С Windows-хоста VM адрес 127.0.0.1 по умолчанию указывает на Windows и не откроет Debian без проброса порта или SSH-туннеля.

## Работа

1. «Объекты ОИ» → создать ОИ (например, `ОИ-001`).
2. «Реестр СВТ» → создать `СВТ-0001`, выбрать ОИ, заполнить серийный номер и ОС.
3. «Конструктор полей» → создать типовое поле «Срок протокола СП» типа дата. Либо в карточке СВТ нажать «Поле только для этой карточки».
4. Открыть карточку СВТ → заполнить пользовательское поле.
5. «Документы» → загрузить реальный протокол/формуляр. Затем в карточке СВТ → «Документальные основания» → выбрать поле, документ, страницу или пункт → «Привязать основание».
6. В «Реестр СВТ» использовать фильтры и «Выгрузить CSV». Формат UTF-8 BOM с разделителем `;` для Excel.

## Резервная копия

```bash
cd /home/admsec/ZGT/CMDB/oi-registry-v0.1
bash scripts/backup.sh
```

Скрипт создаёт два файла: дамп PostgreSQL и TAR.GZ хранилища документов. Дамп без файлов — неполная резервная копия.

## Остановить/запустить

```bash
cd /home/admsec/ZGT/CMDB/oi-registry-v0.1
docker compose stop
docker compose up -d
```

Не выполняйте `docker compose down -v`: `-v` удаляет тома с реестром и документами.

## Безопасность и ограничения

- Только `127.0.0.1:8085` на Debian; наружу публиковать без HTTPS, обратного прокси и необходимых мер защиты **нельзя**.
- Основная учётная запись создаётся вручную на сервере, пароль не хранится в `.env` и не выводится в логах.
- `.env` и `backups` не копировать в Git и не передавать третьим лицам.
- При работе с информацией ограниченного доступа дополнительно необходимы полноценные ролевые политики, разграничение по объектам, аудит чтения, антивирусная проверка файлов, защищённое резервирование и организационные меры.
- PDF позволяет использовать `#page=N` для открытия страницы. Для DOCX/XLSX сохраняется метаданные пункта/ячейки, автоматическое позиционирование внутри документа в v0.1 не реализовано.

## Разработка и тесты

Миграция схемы: `backend/migrations/versions/0001_initial.py`. Тесты запускаются отдельно на SQLite, без изменения PostgreSQL, в окружении с зависимостями из `backend/requirements.txt`:

```bash
python3 -m pytest -q tests/
```

На этапе подготовки пакета проверены Python/JavaScript и локальные функциональные тесты. Docker-стенд Debian + PostgreSQL должен пройти `scripts/smoke.sh` на вашем сервере.
