# OI Registry v0.6.2-alpha — корректировка заявок и CSRF

**Дата:** 20.10.2026. **Статус:** исправление для тестовой v0.6.1, не внедрять в production без проверки. **Миграция:** `0009_requests_no_type` после `0008_registry_v061`.

## Реально изменено

- «Заявки»: удалён обязательный «Тип системы» из таблицы, формы создания и формы изменения; удалён экран «Редактор типов систем». Остаются `Сегмент`, `ФИО`, `IP-адрес`, `Путь скана в SMB`, `СВТ`.
- `RegistryRequestInput`: поле `system_type_id` больше не запрашивается. Новые заявки сохраняются с `NULL`, поскольку миграция разрешает отсутствие типа в PostgreSQL.
- Старые `system_type_id` и справочник `system_types` **сохраняются для совместимости**; при редактировании старой заявки связь не стирается. Старые API справочника пока не удалены.
- Клиент повторно получает CSRF с `/api/auth/me` при диагностированном несовпадении токена и делает только один повтор запроса. Проверка на сервере не отключена. Если серверный секрет сменился, необходим повторный вход.
- Обновлены номера версии браузерных ресурсов для принудительной загрузки JS.

## Ограничения

Проверены Python-тесты на временной SQLite и синтаксис JavaScript. Не подтверждены миграция на пользовательской PostgreSQL, HTTPS и реальные данные. Эта ревизия не решает все возможные причины CSRF 403, связанные с изменением `OI_SESSION_SECRET`. Версия v0.5 на 8085 не должна меняться.
