# OI Registry v0.6.1-alpha — модель СВТ и заявок, HTTPS

**Статус:** изолированный пакет-кандидат, **не внедрён на рабочий сервер**. Дата подготовки: 20.10.2026. Базовая ветка: `feature/oi-registry-v0.6-alpha` с предыдущей миграцией `0007_oi_transfer_approvals`.

## Изменения

1. Паспорт ОИ: добавлено текстовое `attestation_smb_path`; прежний `attestation_document_id` оставлен только ради совместимости.
2. Реестр СВТ: `assets.oi_id` теперь nullable; фильтрация и выборки используют LEFT OUTER JOIN. Форма умеет создать отдельную СВТ, позже закрепить за ОИ; история работ сохраняется.
3. Реестр административных заявок: `registry_requests`; справочник типов `system_types` (необязательная уникальность заявок на тип, тип может повторяться в любой заявке). IP валидируется, путь скана хранится текстом (SMB/UNC), СВТ — необязательная ссылка.
4. CSV СВТ: полный экспорт 15 колонок, импорт с обязательным `preview` и 3 режимами, одноразовым подтверждением перед `commit`. Копирование создаёт новые коды, замена изменяет совпадающие коды без массового удаления. Интеграция с историей ремонта и документами в CSV **не реализована**.
5. Отдельный Compose TLS proxy поверх `oi-web` с `OI_COOKIE_SECURE=true` и примером доступности через VirtualBox NAT/SSH-туннель. Сертификат нужно выпустить/предоставить отдельно.
6. Старые данные `service_requests`, `work_entries`, `oi_proposals` не удалены. Журнал ремонтов в блоке «Состав, работы, проверки», и новый реестр заявок — разные сущности.

## Версии и контроль

- FastAPI version `0.6.1-alpha`, frontend `v0.6.1-alpha`.
- Alembic `0008_registry_v061` (после `0007_oi_transfer_approvals`).
- Проверено локально: **38 Python-тестов**, `alembic upgrade head` 0007 → 0008 на отдельной SQLite.
- Не проверено: PostgreSQL upgrade/restore на рабочем сервере, сквозная работа с SMB, TLS в браузере, испытания по VirtualBox NAT и реальные данные пользователя.
